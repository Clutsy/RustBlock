Built for the whole job

One app, from download
to a model your runtime can load.

No shell scripts, no Python environments, no guessing which quantization will fit. RustBlock opens the source read-only, writes a temporary file, verifies it, then renames it into place.

Twenty-two native targets

Lossless Reblock, floats, legacy quants, K-quants, ternary, MXFP4, NVFP4 and 1-bit. Real encoders written in Rust, not placeholders.

All cores, bounded RAM

Independent tensors encode in parallel. Large tensors are split into block-aligned spans, so all logical cores stay busy without loading the whole model into memory.

Verification before the rename

Structure checks offsets and sizes; Full decodes both copies and compares every tensor. The final file replaces the temporary one only if the check passes.

Discover, sized before download

Search Hugging Face or ModelScope, inspect GGUF files and see a RAM/VRAM fit verdict at 4096 tokens before a multi-gigabyte transfer starts.

Download, inspect, deploy

Resumable downloads, a per-block GGUF inspector, and one-click copy to LM Studio, Jan or Prism, or an Ollama import through a generated Modelfile.

OTA updates

The installed app checks GitHub Releases on launch. When a newer build exists, Settings downloads the release installer and restarts into it.

Three deliberate steps

Nothing is overwritten until it is verified.

The pipeline is deliberately boring: read the source without touching it, write a temporary GGUF beside the destination, compare, then rename. If anything fails, the original stays exactly where it was.

Straight answers

Before you ask.

Does it need Python or llama.cpp?

No. Conversion, quantization, reblocking and verification are native Rust. Optional integrations can call llama-bench, llama-imatrix or Ollama when you have them installed.

Is my model uploaded anywhere?

Never. Conversion is local and offline. Network access is used only for explicit Hub searches, downloads and the update check.

What happens if verification fails?

The temporary output is discarded. The source file was opened read-only and is never modified.

How do updates work?

The installed build asks GitHub for the latest release on launch. Settings shows the new version, downloads the per-user installer and restarts when it is ready.
